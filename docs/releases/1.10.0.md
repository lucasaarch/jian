### Pull requests

* **Every open pull request in one place:** With GitHub connected on a server gateway, **Pull requests** sits in the sidebar below Schedules. It opens where the chat was, so the sidebar stays beside it, and on a phone it opens the way a chat does. It lists the open pull requests of every connected account, up to 50 per account. Each row shows its reviewers, its checks, whether it can merge and when it last changed. Switch between Open, Mine and Needs review, pick a repository, or search. Mine appears when the App is installed on your personal account. Needs review leaves out drafts and anything already approved.
* **An agent reviews it for you:** **Review** on a row hands the pull request to an agent. It gets a new chat named after the pull request, for example `Review octo-example/site#7`, and runs on Auto. The agent reads the changes, posts one review on GitHub with comments on the lines they concern, and sums up what it found in that chat. Once a pull request has an agent review, its row links to that chat.
* **Your rules for reviews:** In **Review settings** you choose the reviewing agent and write the instructions it follows. Jian starts you off with default instructions. With no reviewing agent chosen, Review uses the agent you have open.
* **Reviews that start on their own:** Turn on **Review new pull requests** and the reviewing agent takes each pull request that is opened, reopened or marked ready for review. **Include drafts** adds drafts as soon as they are opened, and you can limit it to some repositories; with none ticked, it covers every repository the App can see. Each new head commit gets one automatic review at most, even when GitHub delivers the event more than once. Jian checks the signature on every delivery before it reads anything in it.
* **The author's text stays out of the agent's instructions:** The message that starts a review carries only the pull request's address, its head commit and your instructions. The agent reads the title and description on GitHub as part of what it reviews, so a pull request can't slip instructions to it there.

### Upgrading

* The desktop app updates itself to this release. Pull requests is for server gateways; a desktop app's own gateway doesn't show it.
* **Servers:** Recreate the gateway and web containers with the 1.10.0 images, or follow the `latest` tags. Migration 0102 runs when the gateway starts.
* **Automatic reviews:** GitHub reaches the gateway at `JIAN_PUBLIC_URL`, on `/v1/integrations/github/webhook`. A GitHub App connected from this release on comes with the webhook set. For an App connected before, open **Pull requests** › **Review settings**, turn on **Review new pull requests** and click **Set up webhook**. Then, in the App's settings on GitHub (**Open the App on GitHub**), subscribe the webhook to the **Pull request** event and make sure it is **Active**. GitHub has no API for that last step. The settings show **Receiving** once the first delivery arrives.
* **API:** `GET /v1/integrations/github/pulls` lists pull requests, with `filter` (`open`, `mine` or `review`), `repository` and `q`. `POST /v1/integrations/github/pulls/{owner}/{repo}/{number}/review` starts a review. `GET` and `PUT /v1/integrations/github/reviews` read and save the review settings, and `POST /v1/integrations/github/reviews/webhook` sets up the App's webhook. `POST /v1/integrations/github/webhook` takes GitHub's signed deliveries.
